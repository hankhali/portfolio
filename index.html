01

Transcendence — Real-Time Multiplayer Platform

Two players on separate networks have to see the same game state at the same moment, and neither browser can be trusted to report its own score. I made the server the single source of truth: it runs the game loop, pushes state over WebSockets, and treats every client message as a request rather than a fact. Around that sits account registration, session authentication, and a matchmaking queue that pairs waiting players.

Architecture NGINX sits in front as the only exposed container, terminating TLS and proxying both ordinary HTTP and the WebSocket upgrade. That keeps the frontend and the game server on one origin — no CORS layer to maintain, one certificate to renew, and the game server never listens on a public port directly.

  • TypeScript
  • Node.js
  • Fastify
  • WebSockets
  • Docker
  • NGINX

02

Poll Voting System

A poll is only credible if one person cannot vote twice and everyone sees the same tally. I built the vote path around that constraint — votes are tied to an authenticated account and validated server-side before they count, and results update live rather than on refresh. The REST API handles poll creation, retrieval and result aggregation as separate concerns, so the read path stays fast while votes are still arriving.

  • TypeScript
  • Node.js
  • REST APIs
  • Docker

03

Inception — Container Infrastructure

Running a web server, an application and a database on one machine means a single bad deploy can take down all three. I separated them into purpose-built containers on a private Docker network, so only the web server is reachable from outside and the database is not exposed at all. Data survives container rebuilds through named volumes, and TLS is terminated at the entry point with certificates I configured myself.

  • Docker
  • Docker Compose
  • NGINX
  • MariaDB
  • Linux
  • TLS

04

IRC Server

One slow client must not stall everyone else on the server. Rather than spawn a thread per connection, I built a single-threaded event loop that multiplexes every socket at once and never blocks on a read or a write. On top of that sits a parser for the IRC wire protocol — channels, private messages, operator commands and authentication — written to handle messages that arrive split across packets or glued together.

  • C++
  • TCP/IP
  • Socket programming
  • Linux

05

Face Recognition System

A general-purpose face model performs poorly on low-resolution video frames it was never trained on. Working to a hackathon deadline, I fine-tuned the Buffalo model against a dataset built from video snippets, reaching 80% accuracy with high precision on the recognition task — precision mattering more than raw accuracy here, because a confident wrong match is worse than no match at all.

  • Python
  • Deep learning
  • Buffalo
  • Computer vision
